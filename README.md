# ХДУ — віртуальна 3D-прогулянка

Сайт Херсонського державного університету з інтерактивною 3D-прогулянкою територією (Three.js).

## Запуск
Сторінка не працює через подвійний клік на `index.html` (браузер блокує модулі й завантаження файлів з диска). Потрібен локальний сервер:
- двічі клікнути `start.bat` (потрібен Python або Node.js), або
- у VS Code встановити розширення **Live Server** → правий клік на `index.html` → *Open with Live Server*.

## Керування
| Дія | Клавіші |
|---|---|
| Ходьба | **W A S D** (або стрілки; працює й в українській розкладці) |
| Огляд на 360° | миша (клік по екрану вмикає захоплення курсору, **Esc** — відпустити) |
| Біг | **Shift** |
| Стрибок | **Space** |
| Прогулянка ⇄ вільний огляд | **F** або кнопки зверху зліва |
| Повернутися на початкову точку | **R** |

Вільний огляд (політ камерою): тягнути мишею — огляд, WASD — рух, Q/E — вниз/вгору, Shift — швидше, колесо — швидкість.
Кнопки «Афіна», «Парк», «Спорт» телепортують гравця на землю, «Огляд зверху» / «Парк зверху» вмикають вільну камеру.

## Як працюють колізії
Модель Blender/GLB **не змінюється**. З неї окремим скриптом генерується 2D-сітка 0.2 м (`data/collision.bin.gz`, ~0.1 МБ): для кожної клітинки — висота поверхні для ходьби (дороги, плитка, бордюри, сходи) та діапазон висот перешкоди.
- Блокують: будівлі, стовбури дерев (і ядро крони ялин/туй), фонтан, статуя Афіни, паркани й ворота, лавки, урни, клумби, ліхтарі, машини, навіси за висотою (під навісом від 3.5 м можна пройти).
- Не блокують: трава, квіти, кущі, листя дерев.
- Гравець — коло радіусом 0.32 м, очі на 1.65 м. Сходинки й бордюри до 0.5 м проходяться автоматично, стрибок ≈ 0.7 м, ковзання вздовж стін.

Після зміни моделі перегенеруйте сітку: `python tools/build_collision.py` (потрібні numpy та scipy; Pillow — для картинки `docs/collision_map.png`). Правила — на початку скрипта (регулярні вирази за назвами вузлів). Параметри гравця (швидкості, висота очей, стрибок) — `js/config.js` → `player`, значення за замовчуванням у `js/player.js`.

## Структура сайту
Одна сторінка `index.html`: шапка з навігацією → Hero → «Про університет» → «Віртуальна екскурсія» (3D-сцена з повноекранним режимом) → «Територія» (5 карток, кожна відкриває відповідне місце в 3D) → футер.
Модель (40 МБ) і Three.js **не вантажаться при відкритті сторінки** — лише після кліку «Розпочати віртуальну екскурсію» чи на картку; повторно модель не завантажується. Коли сцену не видно або вкладка неактивна, рендер зупиняється.

```
index.html            сайт (розмітка, тексти)
css/site.css          дизайн сайту (палітра, типографіка, секції, адаптивність)
css/style.css         інтерфейс 3D-сцени (кнопки, постер, джойстик)
js/site.js            навігація, анімації, ліниве завантаження екскурсії
js/tour.js            3D-прогулянка: рендерер, світло, GLB, режими, повний екран, дотик
js/player.js          керування від першої особи, фізика, колізії гравця
js/collision.js       сітка колізій
js/config.js          модель, сонце, туман, точки огляду (views), старт, параметри гравця
assets/img/           картинки Hero та карток (знімки з 3D-моделі)
data/collision.bin.gz сітка колізій (генерується tools/build_collision.py)
tools/                build_collision.py, build_site.py (збірка для GitHub Pages), читач GLB
.github/workflows/    pages.yml — автопублікація на GitHub Pages
tests/                walk_test.py, site_test.py, fp_shots.py
models/               KSU_campus_clean.glb + backup/
vendor/three/         Three.js r170 (локально, без CDN)
docs/                 MODEL_REPORT.md, collision_map.png
```

### Як змінити тексти
Усі тексти — у `index.html` (українською). Відомості про університет (розділ «Про університет») взято з офіційного сайту https://www.kspu.edu/: рік заснування 1917, «понад століття безперервного розвитку», аспірантура й докторантура, наукові лабораторії/видання/конференції. Нових фактів не додавалось; додавайте лише перевірені.
Картинки в `assets/img/` — знімки з самої моделі; для нових кадрів можна використати `tests/fp_shots.py` як приклад.

### Кнопки локацій
Точки задаються в `js/config.js` → `views`. Якщо висота камери < 10 м — це «наземна» точка (телепорт у прогулянку), інакше — вільна камера. Нову кнопку додайте в `index.html` (`data-view="ключ"`).

## Публікація на GitHub Pages
Сайт статичний: усі шляхи відносні (`models/…`, `data/…`, `vendor/…`, `css/…`), тому він однаково працює і на `localhost`, і в підкаталозі `https://<користувач>.github.io/<репозиторій>/`. Публікацію виконує workflow `.github/workflows/pages.yml`: при кожному `push` у `main` він запускає `tools/build_site.py`, який збирає в `_site` лише потрібне (index.html, css, js, assets, vendor, `data/collision.bin.gz`, `models/KSU_campus_clean.glb`) і перевіряє, що всі шляхи існують. `tests/`, `tools/`, `docs/`, резервні копії та старий GLB не публікуються.

**Один раз створіть репозиторій і завантажте файли** (рекомендована назва — `ksu-virtual-tour`):
1. На https://github.com/new: Repository name = `ksu-virtual-tour`, **Public** (на безкоштовному акаунті Pages працює лише з публічними), без галочок «Add README / .gitignore / license» → *Create repository*.
2. У папці проєкту (`Documents\KSU_web`) відкрийте PowerShell або cmd і виконайте:
   ```
   git init -b main
   git add .
   git status
   git commit -m "Сайт ХДУ з 3D-прогулянкою"
   git remote add origin https://github.com/arkadiyfidiy444/ksu-virtual-tour.git
   git push -u origin main
   ```
   Якщо `git` не встановлено — https://git-scm.com/download/win. Під час `push` відкриється вікно входу в GitHub (Git Credential Manager) — увійдіть своїм акаунтом.
   Без командного рядка: **GitHub Desktop** → File → Add local repository → Publish repository (зніміть «Keep this code private»).
   ⚠ Не завантажуйте файли перетягуванням у веб-інтерфейсі: GLB (~40 МБ) перевищує ліміт веб-завантаження (25 МБ). Потрібен `git` або GitHub Desktop. Окремий файл не повинен бути більшим за 100 МБ (GLB — 40 МБ, тож LFS не потрібен).
3. У репозиторії: **Settings → Pages → Build and deployment → Source = GitHub Actions**.
4. Вкладка **Actions** → «Deploy to GitHub Pages» (запускається автоматично після push; за потреби — *Run workflow*). Коли позначка зелена, сайт доступний за адресою
   `https://arkadiyfidiy444.github.io/ksu-virtual-tour/`

**Оновлення сайту:** змініть файли, потім `git add .`, `git commit -m "опис"`, `git push` — workflow опублікує нову версію (1–3 хв).

**Перевірка перед публікацією (необов'язково):** `python tools/build_site.py` збере `_site` і виведе помилку, якщо якийсь шлях зламаний.

**Типові проблеми**
- Сторінка 404 одразу після першого push — Pages ще не ввімкнено (крок 3) або workflow ще виконується.
- Workflow червоний на кроці `configure-pages` — не вибрано Source = GitHub Actions.
- «Не вдалося завантажити 3D-модель» — відкрийте консоль браузера (F12 → Network) і подивіться, який файл дає 404; перевірте, що `models/KSU_campus_clean.glb` і `data/collision.bin.gz` потрапили в репозиторій (`git ls-files`).
- Після оновлення видно стару версію — жорстке оновлення Ctrl+F5 (GitHub Pages кешує файли до 10 хвилин).
- Перше відкриття завантажує ~40 МБ моделі; далі браузер бере її з кешу.
- Локальна робота не змінюється: `start.bat` запускає сайт, як і раніше.

## Продуктивність 3D (слабкі ПК / інтегрована графіка)
- Усередині сцени немає CSS-розмиття (`backdrop-filter`) і округлого обрізання — вони змушують браузер перераховувати їх поверх WebGL у кожному кадрі.
- «Прогрів» GPU під час завантаження (шейдери, текстури, геометрія), щоб не було фризів, коли об'єкт уперше потрапляє в кадр.
- Авто-якість: якщо кадри повільні, внутрішня роздільність canvas плавно знижується (×0.85 → ×0.55) і повертається, коли запас є. «Показати FPS» у ⚙ показує поточну роздільність.
- Коли камера не рухається, кадр не перемальовується; поза екраном або у фоновій вкладці рендер зупинений.
- Найплавніше — режим «Повний екран».

## Тести
Потрібен Playwright + Chromium і запущений сервер.
- `python tests/site_test.py [url]` — сайт: посилання, навігація, ліниве завантаження, картки, кнопки, повний екран, мобільна версія.
- `python tests/walk_test.py [url]` — керування й колізії: швидкості, стрибок, висота очей, будівлі/дерева/фонтан/паркан, сходи.

## Експорт моделі з Blender
Файл → Експорт → glTF 2.0 (.glb), у блоці *Include* увімкнути **Visible Objects**: так колекція `_SRC_instances` (вимкнена в Blender) не потрапляє в GLB. Решта налаштувань за замовчуванням.
